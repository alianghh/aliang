代理与 VPS 入门

上网，就是你的电脑和世界各地的电脑互相寄包裹。代理的意思是：包裹先寄给你在海外租的一台电脑，由它替你转寄，回信也由它转给你。这一页从"地址怎么写"讲起，一直讲到一台自建 VPS 上跑着什么。

先记住这五句话

  • IP 是门牌号，端口是房间号，域名是名字，DNS 是把名字查成门牌号的通讯录。
  • TCP 像打电话，确认对方听到才往下说；UDP 像寄明信片，寄出去就不管了。
  • 系统代理只管"听话"的程序的 TCP 流量；TUN 模式接管整台电脑的全部流量。
  • 路由规则决定每个包裹走哪条路：国内直连，国外走代理，少数直接拦下。
  • 你的节点链接（vless://…）就是服务器的钥匙，不要发给别人，截图记得打码。

第 1 章

网络上的地址：IP、端口、域名、DNS

寄快递要写地址，网络也一样。每个数据包上都写着"从哪来、到哪去"。地址由几部分组成：

IP 地址 像门牌号
每台联网设备都有，长这样：104.16.249.249（IPv4），或更长的 2606:4700::1111（IPv6）。
端口 像房间号
一台电脑上有 1 到 65535 号"房间"，不同程序守在不同房间。写在 IP 后面，用冒号隔开：IP:端口。
域名 像名字
www.google.com 这样好记的名字。电脑真正连接时，要先把名字换成 IP。
DNS 像通讯录
负责把域名查成 IP 的服务。如果有人在你查的时候塞给你一个假地址，就叫 DNS 污染。

三种特别的 IP

  • 公网 IP：全世界都能找到的门牌号。VPS 都有一个固定的公网 IP。
  • 内网 IP：只在家里、宿舍、学校内部有效，常见的是 192.168.x.x、10.x.x.x。路由器后台一般是 192.168.1.1。
  • 127.0.0.1：永远指"这台电脑自己"。包裹不出门，只是交给本机上的另一个程序。

    第 2 章

    数据怎么送：TCP 和 UDP

    地址写好了，接下来是"怎么送"。网络上最常用的送法有两种。

    TCP：像打电话

    • 先握手，确认对方在线
    • 每段数据都要回执，丢了重发
    • 按顺序到达，不缺不重
    • 代价：多了来回确认，稍慢

    谁在用：网页、下载、SSH、VLESS 节点

    UDP：像寄明信片

    • 不握手，直接发
    • 不回执、不重发
    • 可能乱序、可能丢
    • 好处：快，延迟低

    谁在用：语音视频通话、游戏、直播、DNS、QUIC

    为什么通话和游戏要用 UDP

    半秒钟前的一句话，就算重发回来也已经没用了，不如丢掉继续往下说。游戏里你角色的位置也是同理，只有最新的位置有意义。所以这类程序宁可偶尔丢一点，也不愿等。

    第 3 章

    网页是怎么说话的：HTTP、HTTPS、TLS、QUIC

    HTTP
    浏览器和网站之间对话的格式。"请给我这个页面"，"给你"。
    TLS 像保险信封
    加密层。内容装进只有双方能拆开的信封，路上的人看不到里面写了什么。
    HTTPS
    HTTP 加上 TLS。浏览器地址栏的小锁就表示用的是它。
    证书 像身份证
    网站出示的身份证明，由权威机构签发，证明"我真的是 google.com"。

    信封外面还写着名字：SNI

    TLS 能把信的内容藏起来，但在加密开始之前，浏览器得先说一句"我要找 www.google.com"，好让对方拿出对应的证书。这句话写在信封外面，叫 SNI（服务器名称指示）。路上的人看得到它，审查系统也就能据此判断你要去哪。第 8 章讲的 REALITY 伪装，就是从这里下手的。

    HTTP/3 和 QUIC

    HTTP 有好几代。前几代都跑在 TCP 上，最新的 HTTP/3 改成跑在 QUIC 上，而 QUIC 是建在 UDP 上的，用的是 UDP 443 端口。它把 TCP 的可靠和 TLS 的加密都自己做了一遍，在手机网络这种不稳定的环境下更快。

    老办法
    新办法
    网页层
    HTTP/1.1、HTTP/2
    HTTP/3
    加密层
    TLS
    QUIC（自带加密和重发）
    送法
    TCP 443
    UDP 443
    地址

    浏览器的做法是：能用 HTTP/3 就用，用不了就自动换回 HTTP/2（走 TCP）。所以 QUIC 被挡，网页照样打开，你基本感觉不到区别。

    第 4 章

    为什么需要代理，代理又是什么

    在国内直接访问一部分境外网站是打不开的。跨境的网络出口处有一套审查系统（常被叫作"防火长城"，简称"墙"或 GFW），它主要用这几种办法：

    • DNS 污染：你查 google.com 在哪，它抢先塞给你一个错误的 IP。
    • 封 IP：发往某些 IP 的包直接丢掉。
    • 看 SNI 和流量特征：信封外写着被禁的名字，或者包裹"长得像代理"，就切断连接。

    代理就是请人跑腿

    你不直接去目标网站，而是把请求交给一个在境外的帮手。帮手替你去取，再把结果交给你。审查系统只看到你在和这个帮手通信。

    关键在于伪装。如果你和帮手之间的通信一看就是代理，帮手的 IP 很快就会被封。各种代理协议（VLESS、Trojan、Shadowsocks……）和伪装技术（REALITY）的区别，主要就在于怎么让这段通信看起来像普通上网。

    节点
    一个能用的帮手：一台服务器，加上连接它需要的全部参数。
    机场 / 自建
    机场是别人运营、卖给很多人用的节点服务。自建是自己租 VPS 搭的，只有自己用。
    客户端
    用户这边负责打包的软件，比如电脑上的 v2rayN、iPhone 上的 Shadowrocket。
    服务端
    VPS 上负责拆包的软件，常见的是 Xray，常用网页面板 3x-ui 来管理。

    第 5 章

    电脑上的 v2rayN 在做什么

    外壳和内核

    v2rayN 本身只是一个"遥控器"（图形界面），真正处理流量的是它调用的内核。开着 TUN 时，任务管理器里能看到三个进程：

    进程角色负责什么
    v2rayN.exe遥控器界面、保存设置、启动和停止内核
    xray.exe打包员按 VLESS 协议加密、伪装，和你的 VPS 通信
    sing-box.exe总闸开 TUN 模式时，接住整台电脑的流量

    入站、路由、出站

    每个内核内部都像一个快递分拣站：

    入站 收件窗口
    包裹从这里进来。v2rayN 默认在 127.0.0.1:10808 开一个窗口，HTTP 和 SOCKS 两种格式都收。
    路由 分拣员
    按规则逐条比对，决定每个包裹从哪个出口走。
    出站 发货口
    三个口：proxy 寄给 VPS，direct 直接送不绕路，block 直接扔掉。
    DNS 分流
    v2rayN 的默认配置里，国内域名问腾讯的 119.29.29.29，快且就近；国外域名经过代理去问 Cloudflare 的加密 DNS，防污染。

    系统代理和 TUN，差在哪

    系统代理 门口贴告示
    在 Windows 设置里写上"要上网的请走 127.0.0.1:10808"。浏览器会照做，但很多程序不看告示（游戏、部分通话软件、命令行工具）。而且告示只管 TCP，UDP 根本不归它管。
    TUN 模式 出入口装闸机
    装一块虚拟网卡（v2rayN 里叫 singbox_tun），设成电脑的默认出口。所有程序的所有流量，TCP 和 UDP，都先经过它。需要管理员权限才能开启。

    系统代理和 TUN 同时开着时的完整链路

    两者可以同时开，不冲突：看告示的程序直接去 10808，不看告示的被 TUN 接住，最后汇到同一个地方。

    1. 某个程序发出请求浏览器、游戏、通话软件……
    2. TUN 虚拟网卡接住，交给 sing-boxsing-box 按规则做第一次分拣（国内直连 / 拦截 / 交给代理）
    3. 交给 127.0.0.1:10808 的 Xray看系统代理告示的程序直接到这一步
    4. Xray 第二次分拣，加密打包VLESS 协议 + REALITY 伪装
    5. 穿过跨境出口，到你的 VPSVPS 上的 Xray 拆包
    6. VPS 替你访问目标网站对网站来说，访问它的是 VPS 的 IP

    分拣规则：「绕过大陆」

    以 v2rayN 自带的规则集「V4-绕过大陆(Whitelist)」为例，规则从上往下逐条比对，命中第一条就停：

    1. UDP 443（QUIC）拦截
    2. Google 相关域名代理
    3. 内网地址（192.168.x.x 等）直连
    4. 国内 DNS 服务器直连
    5. 国内 IP（geoip:cn）直连
    6. 国内网站（geosite:cn）直连
    7. 以上都不是（兜底）代理

    geosite 和 geoip 是两本"地址簿"：geosite 按域名分类（哪些是国内网站、哪些属于 Google），geoip 按 IP 分类（哪些 IP 在中国）。地址簿可以在 v2rayN 里更新。

      第 6 章

      检测工具说"UDP 出不去，QUIC 被挡"，是怎么回事

      有的网络检测工具会提示："UDP 出不去，QUIC 被挡：视频通话、游戏和 HTTP/3 会退回 TCP，或者干脆连不上。"在一台开着 v2rayN（系统代理 + TUN，规则集「绕过大陆」）、用 VLESS + REALITY 节点的电脑上实际测一遍，结果是这样：

      测试送法结果
      问 Google 的 STUN 服务器"我的 IP 是多少"UDP 19302通 回答的是 VPS 的 IP
      问 Cloudflare 的 STUN 服务器UDP 3478通 同样走的代理
      向 www.google.com 发 QUIC 包UDP 443无回应
      向 cloudflare.com 发 QUIC 包UDP 443无回应

      结论：UDP 是通的，只有 UDP 443 被拦。原因就是上一章规则表的第 1 条，在 v2rayN 里叫「阻断udp443」。检测工具拿 QUIC 代表 UDP 来测，所以说成了"UDP 出不去"，这个说法不准确。

      v2rayN 为什么默认拦掉 QUIC

      VLESS + REALITY 这类节点走的是 TCP。QUIC 想经过代理，就得先被装进 TCP 隧道，好比把明信片塞进挂号信里寄。TCP 的"丢了重发"会打乱 QUIC 自己的调速和重发，结果常常比直接用 TCP 还慢。干脆拦掉，浏览器立刻改用 TCP，反而更稳。

      要不要改

      一般不用。网页、视频都正常，普通 UDP（通话、游戏常用的端口）也通。只有某个程序非得用 UDP 443 才能连上时，再考虑关掉这条规则：

      1. 打开 v2rayN 的「设置 → 路由设置」。
      2. 双击「V4-绕过大陆(Whitelist)」。
      3. 找到「阻断udp443」，取消勾选「启用」，点确定。
      4. v2rayN 会重载内核，代理会断一两秒，挑个不碍事的时候自己操作。

      第 7 章

      VPS：服务器那头有什么

      VPS（虚拟专用服务器）是在海外机房租的一台"云电脑"：24 小时开机，有固定的公网 IP，装的是 Linux 系统（常见 Ubuntu、Debian）。它一般没有图形界面，全靠敲命令操作，按月付费。

      怎么控制它

      SSH 远程命令行
      一种加密的远程登录方式，默认走 TCP 22 端口。你在这头敲的命令，都在 VPS 上执行。
      Xshell
      Windows 上常用的 SSH 客户端。用它打开的那个黑色窗口，就是 VPS 的命令行。
      密码登录 / 密钥登录
      密码像暗号，别人可以不停地猜。密钥是一对文件：公钥放在服务器上，像一把锁；私钥留在你电脑里，像唯一的钥匙。只认钥匙的门，猜不开。
      3x-ui 面板
      装在 VPS 上的网页版管理后台，用来添加、修改节点，看流量。它背后管理的就是 Xray。面板本身也是一个入口，所以要有强密码、随机路径和两步验证（动态码）。
      私钥丢了怎么办

      只认密钥的服务器，私钥丢了就从 Xshell 登不上了。这时可以去 VPS 商家的网页后台，用"VNC 控制台"或"救援模式"登录，重新放一把公钥。私钥文件建议备份一份到安全的地方，但不要发给任何人。

      服务器上的几层防护

      一台自建 VPS 常见的几层防护，从外到内：

      1. 防火墙（ufw）只放行用得到的端口（SSH、节点端口），其余一律关上。
      2. fail2ban发现同一个 IP 反复登录失败，就自动把它拉黑一段时间。
      3. SSH 只允许密钥登录关掉密码登录，猜密码的机器人就没了用武之地。
      4. 面板加固强密码、非默认路径、两步验证动态码。
      5. 自动安全更新系统漏洞的补丁自动打上，不用你记着。

      BBR：让跨国线路跑得更快

      BBR 是 Google 做的一种 TCP 调速方法（叫"拥塞控制算法"）。跨国线路经常丢包，老办法一遇到丢包就大幅减速；BBR 按实际带宽和延迟来调速，跨国传输通常快不少。开启之后不用管它。

      线路、延迟和丢包

      延迟（ping）
      一个包一来一回要多少毫秒（ms）。国内到日本、新加坡一般几十毫秒，到美国通常一百多到两百多毫秒。
      丢包
      包在路上丢掉的比例。晚上高峰期丢包变多，就会卡、会断。
      去程 / 回程
      你到 VPS 和 VPS 到你，可能走不同的路。看视频、下载主要靠回程。
      优化线路
      电信 CN2 GIA、联通 9929、移动 CMIN2 等是运营商的高质量国际线路，晚高峰更稳，价格也更高。

      IP 被封是什么样子

      如果你和 VPS 的通信被认出来，审查系统可能封掉 VPS 的 IP 或某个端口。典型表现是：国内连不上 VPS，但从国外测它一切正常。处理办法有换端口、换 IP（很多商家可以付费更换）、换协议。

      REALITY 是怎么骗过检查的

      1. 你的客户端打招呼时说"我要找 www.microsoft.com"（SNI），同时在招呼里悄悄夹带一个暗号。暗号是用公钥算出来的，只有你的服务器能验证。
      2. VPS 检查暗号。对得上，就接待你，开始代理；对不上（比如审查系统主动来试探），就把连接原样转给真正的微软网站，对方拿到的是货真价实的微软证书。

      第 9 章

      藏住真实 IP：泄露、指纹，以及代理做不到的事

      开着代理时，网站看到的应该是你 VPS 的 IP。但真实 IP 还可能从几条小路漏出去；而且网站就算不看 IP，也有别的办法认出你。这一章讲这两件事。

      先分清两个 IP

      真实 IP
      家庭宽带、学校或公司网络分配的公网 IP。它能定位到城市和运营商；这些网络一般都是实名的，所以它能对应到你本人。
      出口 IP 也叫落地 IP
      网站通过代理看到的 IP，也就是你 VPS 的 IP。"藏住真实 IP"，就是让所有流量都只露出这个 IP。

      谁能看到什么

      谁能看到看不到
      你访问的网站VPS 的 IP；你的浏览器指纹；你登录的账号和 Cookie你的真实 IP（前提是没有泄露）
      本地网络（运营商、学校、公司）和审查系统你在和一个海外 IP 通信；流量多大、什么时间；伪装用的 SNI你实际访问了哪些网站，内容是什么
      VPS 商家你的真实 IP（你每天都连它）；注册和付款信息；VPS 往外连了哪些地址HTTPS 加密的内容
      VPS 上的 Xray / 3x-ui如果开着访问日志，会记下访问过的域名HTTPS 加密的内容
      代理不等于匿名

      代理解决两件事：能打开被封的网站，以及网站看不到你本地的 IP。它不保证"没人知道是你"。VPS 是用你的账号和付款方式买的；自建节点的出口 IP 只有你一个人在用，你在各个网站上的活动都能通过这个 IP 串起来；登录了账号，网站当然知道是你。

      四种常见的泄露

      最容易被忽略的两件事 一是 v2rayN 里的 Tun 开关被关上了，只剩系统代理在工作，自己却没发现；二是所在的网络（很多校园网和家庭宽带）分配了公网 IPv6 地址，而代理只接管了 IPv4。下面的泄露里，有几种正好对应这两点。

      1. DNS 泄露

      是什么
      网页本身走了代理，"查域名"这一步却直接问了本地的 DNS（比如运营商或学校的 DNS）。这样本地网络就知道你要去哪些网站。
      什么时候发生
      不看系统代理告示的程序，会用系统设置的 DNS 查询。Windows 还有个老习惯：同时向所有网卡的 DNS 发查询，谁先回答用谁的。
      v2rayN 的情况
      浏览器走系统代理时，域名原样交给 Xray，由代理那头去解析，不经过本地 DNS。TUN 开着时，sing-box 会接住所有 53 端口的查询；如果 Tun 设置里开了"严格路由"（strict_route），它还会加防火墙规则，堵住 Windows 向其他网卡乱发查询。TUN 关着时，其他程序的查询都交给本地网络的 DNS。
      怎么查
      打开 browserleaks.com/dns。结果里应该只有 Cloudflare 这类境外 DNS；出现你学校或运营商的名字，就是泄露。国内网站的域名本来就交给 119.29.29.29 直接查询，这是规则有意安排的，不算泄露。

      2. WebRTC 泄露

      是什么
      WebRTC 是浏览器里做音视频通话的技术。为了打通连接，它会用 STUN（第 6 章测试用的那个）查出你的公网 IP，网页里的脚本可以读到结果。
      什么时候发生
      STUN 走 UDP，系统代理管不了 UDP。只开系统代理时，网页很可能通过 WebRTC 拿到你的真实 IP。TUN 开着时，IPv4 的 STUN 会被接住走代理，查到的是 VPS 的 IP，第 6 章的测试就是这样。
      怎么防
      保持 TUN 打开。Chrome 或 Edge 可以装 Google 官方的 WebRTC Network Limiter 扩展，选"只通过代理"的那一项；Firefox 可以在 about:config 里把 media.peerconnection.enabled 改成 false，代价是网页里的视频通话用不了。
      怎么查
      打开 browserleaks.com/webrtc，看 Public IP 那一栏。

      3. IPv6 泄露

      是什么
      很多网络同时有 IPv4 和 IPv6 两套地址。如果代理只接管 IPv4，访问支持 IPv6 的网站时，流量可能直接从 IPv6 出去，露出你真实的 IPv6 地址。
      容易出问题的情况
      很多校园网和家庭宽带都会分配公网 IPv6。如果 v2rayN 的 Tun 设置里"启用 IPv6 地址"是关着的，TUN 就只接管 IPv4。这时就算 TUN 开着，不走系统代理的程序发出的 IPv6 流量也会绕过它，直接从本地网络出去。浏览器走系统代理时不受影响，但 WebRTC 走的是 IPv6 时同样会漏。
      怎么防
      二选一，都需要你自己操作，改的时候网络会短暂断开：在 v2rayN 的 Tun 模式设置里打开"启用 IPv6 地址"，让 TUN 把 IPv6 也接住（如果 VPS 本身没有 IPv6，这些连接会失败，程序一般会自动改用 IPv4）；或者在 Windows 的 WLAN 网卡属性里取消勾选 IPv6，少数只走 IPv6 的服务会因此用不了。
      怎么查
      打开 test-ipv6.com。如果它显示了 IPv6 地址，而且这个地址属于你本地的网络而不是 VPS，就是泄露。

      4. 程序绕过代理，或代理意外断开

      是什么
      只开系统代理时，不看告示的程序一直在用真实 IP 上网。另外，v2rayN 崩溃、被关掉，或者 Tun 开关被关上时，电脑会直接用真实网络，不会提醒你。
      怎么发现
      任务管理器里没有 sing-box.exe，或者 v2rayN 主界面底部的"启用 Tun"没打开，就说明 TUN 没在工作。
      怎么防
      在 v2rayN 主界面底部重新打开"启用 Tun"（需要以管理员身份运行 v2rayN），打开时网络会短暂切换一下。做对 IP 敏感的事之前，先去 IP 检测网站看一眼出口 IP。

      IP 本身也有"身份"

      网站可以查 IP 数据库，知道一个 IP 属于哪家公司、是什么类型。自建 VPS 用的一般是机房 IP（数据中心 IP），一查就知道是云服务器。有些网站（流媒体、部分 AI 服务、银行）对机房 IP 更严格：多弹验证码、限制部分内容，个别会直接拒绝。商家宣传的"住宅 IP""原生 IP"，指的是看起来像普通家庭宽带、或者登记在当地的 IP。

      网站不看 IP 也能认出你：浏览器指纹

      网站可以用脚本收集你浏览器和电脑的一大堆小特征：屏幕尺寸、系统和浏览器版本、时区、语言、显卡型号、装了哪些字体、画图时像素的细微差别……单看每一项都很普通，组合起来却往往独一无二，这就叫浏览器指纹。换 IP、清 Cookie 都改变不了它。

      更直接的认人办法：Cookie 和账号

      网站最常用的认人办法，其实是 Cookie（网站存在你浏览器里的小纸条）和你登录的账号。只要登录了，换什么 IP 网站都知道是你。无痕窗口关闭后会清掉这次的 Cookie 和记录，但它不隐藏 IP，也不改变指纹。

      怎么减少指纹

      • 目标是"和大家一样"，而不是与众不同。装一堆插件、改冷门设置，反而让你更容易被认出来。
      • Tor Browser 和 Mullvad Browser 让所有用户的指纹尽量一模一样，连窗口大小都按固定档位来。
      • Brave 浏览器默认会给 Canvas 等指纹加随机干扰；Firefox 有"抵抗指纹"的开关（about:config 里的 privacy.resistFingerprinting），开了以后时区会显示成 UTC，部分网站可能显示异常。
      • 时区、语言和 IP 对不上也是线索：IP 在国外，时区却是北京时间、语言是中文。普通上网不用在意。

      指纹浏览器是什么

      指纹浏览器（也叫反检测浏览器）能开出很多个互相隔离的"浏览器环境"。每个环境有自己伪造的一套指纹、独立的 Cookie，通常还绑定一个单独的代理 IP。在网站看来，每个环境都像一台不同的电脑。它主要用在跨境电商、社交媒体运营这类要同时管理很多账号的场景。

      • 它解决的是"让几个账号看起来像不同的人"，并不能让你匿名。日常上网用不着它。
      • 大多是商业闭源软件，你所有账号的登录状态都存在它那里，很多还会同步到它的服务器，等于把这些账号的钥匙交给了它。这类软件出过客户端或插件被入侵、用户加密货币钱包被盗的事故。
      • 很多平台的用户协议禁止一人多号，用它批量开号、养号，可能导致封号。
      • 伪造得不自洽（比如自称 Mac，显卡却是 Windows 电脑的型号）反而更显眼。

      真的需要匿名时：Tor

      Tor 会把你的流量经过三台志愿者服务器层层转发。每一台只知道上一站和下一站，没有任何一方能同时知道"你是谁"和"你在访问什么"。代价是很慢，很多网站会弹验证码。在国内直接连不上 Tor 网络，可以在 Tor Browser 的连接设置里选择通过代理连接，类型选 SOCKS5，地址填 127.0.0.1，端口填 10808（v2rayN 的收件窗口）。这样 VPS 商家能看到你在用 Tor，但看不到你通过 Tor 访问了什么。

      安全守则与排错

      这些东西不要给别人

      • 节点链接 / 二维码
        等于把服务器借给对方用
      • UUID
        节点的账号密码
      • 面板地址 + 账号 + 动态码
        拿到就能改你的全部节点
      • SSH 私钥文件
        拿到就能登录你的 VPS
      • VPS 商家后台账号
        拿到就能重装、删除服务器
      • 带以上信息的截图
        发截图前先打码
      • 面板和 VPS 后台的密码不要和其他网站重复。
      • 网上的"一键脚本"只用来源可靠的（GitHub 上长期维护、使用者多的项目）。
      • 隔一段时间看看 3x-ui 里的流量统计，有异常的大流量要警惕。
      • Shadowrocket 是付费 App，需要外区 Apple ID 从官方 App Store 下载，不要装来路不明的版本。

      连不上时，按这个顺序查

      1. 是不是只有一个网站打不开？是的话，多半是那个网站自己的问题，或者它被分到了直连。
      2. 在 v2rayN 里测一下节点延迟。有数字说明节点通，问题在本机设置或规则；显示超时或 -1，接着往下查。
      3. 国内网站能开吗？国内也打不开，就是你本身的网络断了（比如校园网掉线）。
      4. Xshell 能连上 VPS 吗？连不上，可能是 VPS 宕机、欠费或 IP 被封，去商家后台看状态；能连上，就到 3x-ui 首页看 Xray 是否在运行。
      5. 判断 IP 是否被封。用国内的在线 ping 工具测 VPS 的 IP，再用国外的工具测。国内全部不通、国外正常，基本就是被封了。
      6. 换个网络试试。开手机热点再连。校园网、公司网络有时会限制特定端口或协议。
      "测速失败"不一定是节点坏了

      v2rayN 的测速分两种：延迟测试只看能不能连上、多快回应；下载测速会真的去下载一个境外的测试文件。如果测试文件的地址本身挂了，下载测速也会显示失败，但你上网可能完全正常。以延迟测试和实际使用为准。
